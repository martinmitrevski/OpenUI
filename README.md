# OpenUI for SwiftUI

A native SwiftUI renderer for [OpenUI](https://github.com/thesysdev/openui), the open standard for generative UI. Models answer in **OpenUI Lang**, a compact, streaming-friendly language, and this framework parses it as it streams and renders it with native SwiftUI components: cards, tables, charts, forms, tabs, follow-ups and more.

It's a Swift implementation of the spec, not a web view: the parser, streaming parser, evaluator, reactive state, `Query`/`Mutation` tools, actions and the prompt generator are all ported from `@openuidev/lang-core` and tested against it.

| Folder | What it is |
| --- | --- |
| `OpenUI/` | The framework (iOS 17+, macOS 14+, Swift 6). No dependencies. |
| `OpenUITests/` | Swift Testing suite, including conformance tests against fixtures generated by the upstream TypeScript implementation. |
| `OpenUISample/` | Demo app: a chat with an **OpenUI / Markdown** switch, plus a gallery of the library examples. |
| `OpenUISampleUITests/` | End-to-end UI tests of the demo app against the sample backend. |
| `SampleBackend/` | Node backend for the demo: scripted answers out of the box, live answers from Claude or OpenAI with an API key. See its [README](SampleBackend/README.md). |

## Run the demo

1. Start the backend. Demo mode needs no API key and no `npm install`:

   ```sh
   cd SampleBackend
   npm start
   ```

2. Open `OpenUI.xcodeproj`, select the **OpenUISample** scheme and run it on an iOS simulator.

Try a suggestion such as *Plan a 3-day trip to Ohrid*, then switch the toolbar to **Markdown** to see the same answer as a regular chat would show it; switch back for the rich version. Each answer keeps both versions, and the other one is written the first time you switch. The OpenUI answers are interactive: photo cards and follow-ups continue the conversation, filters re-run live queries against the backend's mock tools, and *Save trip* and *Add to shopping list* run mutations. Photos are looked up on Wikipedia when they're requested, so live answers get real photos for any place, not just Ohrid.

For live answers, run `npm install`, set `ANTHROPIC_API_KEY` (Claude) or `OPENAI_API_KEY` (OpenAI) and start the backend again. Details are in the [backend README](SampleBackend/README.md).

## Using the framework

The framework is the `OpenUI` target in `OpenUI.xcodeproj`; link `OpenUI.framework` to your app.

### Render a response

```swift
import OpenUI

OpenUIView(response: text, isStreaming: isStreaming, library: .openUIChat) { event in
    if event.isContinueConversation { send(event.humanFriendlyMessage) }
}
```

Pass the **full text so far** on each update; the streaming parser only re-parses what changed. Two libraries ship with the framework, matching upstream:

- `.openUIChat` is for chat messages. Every answer is a single vertical `Card`.
- `.openUI` is the standard library, with a `Stack` root, modals and flexible layouts for full-screen generative surfaces.

### Chats: one runtime per message

In a chat, keep an `OpenUIRuntime` per assistant message so its state, form values and query results survive scrolling:

```swift
let runtime = OpenUIRuntime(library: .openUIChat, toolProvider: tools, initialState: savedState)
runtime.onAction = { event in
    switch event.type {
    case BuiltinActionType.continueConversation:
        // Show event.humanFriendlyMessage; send event.assistantMessage (it carries what was
        // clicked and the form state) to the model.
        chat.send(display: event.humanFriendlyMessage, payload: event.assistantMessage)
    case BuiltinActionType.openURL:
        if let url = event.url { openURL(url) }
    default:
        break
    }
}
runtime.onStateUpdate = { state in savedState = state } // persist with the message

// As the answer streams:
runtime.update(response: textSoFar, isStreaming: true)
// When it ends (queries start running now):
runtime.update(response: fullText, isStreaming: false)

// In the message view:
OpenUIView(runtime: runtime)
```

`@Run`, `@Set` and `@Reset` steps, form validation and `$binding` updates are handled by the runtime. Only conversation and navigation actions reach `onAction`.

To send the conversation back to the model, wrap persisted state into the assistant message the way upstream does: `MessageEnvelope.wrap(content: program, context: [.object(state)])`. The demo app's `ChatStore` shows the whole flow.

### Tools for `Query()` and `Mutation()`

Generated UIs fetch live data with `Query("tool", args, defaults)` and write with `Mutation(...)`. Give the runtime a tool provider:

```swift
let tools = FunctionToolProvider([
    "search_hotels": { arguments in
        try await api.searchHotels(city: arguments["city"]?.stringValue ?? "")
    },
])
```

Or conform your own type to `OpenUIToolProvider`. `MCPToolProvider` adapts an MCP client.

### System prompt

The prompt generator is a byte-for-byte port of upstream's `generateSystemPrompt`, so you can generate prompts on the device or ship them to your backend:

```swift
var options = ComponentLibrary.openUIChat.defaultPromptOptions
options.tools = [.spec(ToolSpec(
    name: "search_hotels",
    description: "Search hotels in a city",
    inputSchema: ["type": "object", "properties": ["city": ["type": "string"]], "required": ["city"]],
    outputSchema: ["type": "object", "properties": ["hotels": ["type": "array"]]]
))]
let prompt = ComponentLibrary.openUIChat.systemPrompt(options)
```

`library.specJSON` is the library in upstream's `LibrarySpec` format, for servers that generate the prompt with `@openuidev/lang-core`.

### Customizing

Theme the built-in components:

```swift
var theme = OpenUITheme()
theme.colors.accent = .indigo
theme.radius.large = 20

ContentView().openUITheme(theme)
```

Replace a renderer and keep its schema, so prompts and validation are unchanged:

```swift
let library = ComponentLibrary.openUIChat.replacingRenderer(for: "Callout") { context in
    AnyView(MyCallout(title: context.props.text("title") ?? ""))
}
```

Or define your own components and library with the schema DSL (the Swift equivalent of upstream's Zod schemas):

```swift
let tripCard = ComponentSchema("TripCard", description: "A trip with its length in days", props: [
    .required("title", .string),
    .optional("days", .number),
])
let trips = ComponentSchema("Trips", description: "A list of trips", props: [
    .required("items", .array(.component("TripCard"))),
])

let library = ComponentLibrary(root: "Trips", components: [
    ComponentDefinition(trips) { context in
        VStack(alignment: .leading) { context.render(prop: "items") }
    },
    ComponentDefinition(tripCard) { context in
        Text("\(context.props.text("title") ?? "") · \(Int(context.props.number("days") ?? 0)) days")
    },
])
let prompt = library.systemPrompt() // lists TripCard(title: string, days?: number)
```

`MarkdownView(text)` is also public. The demo app uses it for its Markdown mode.

## How it maps to upstream

| Upstream (`@openuidev/*`) | Swift |
| --- | --- |
| `createParser`, `createStreamParser`, `mergeStatements` | `OpenUIParser`, `OpenUIStreamParser`, `StatementMerger` |
| Evaluator, `@`-builtins, `Action([...])` plans | `Evaluator`, `Builtins` |
| `createStore`, `createQueryManager`, `useOpenUIState` | `OpenUIStore`, `QueryManager`, `OpenUIRuntime` |
| `defineComponent` + Zod, `createLibrary` | `ComponentSchema`, `ComponentDefinition`, `ComponentLibrary` |
| `openuiChatLibrary`, `openuiLibrary` | `ComponentLibrary.openUIChat`, `ComponentLibrary.openUI` |
| `generateSystemPrompt` | `PromptGenerator`, `ComponentLibrary.systemPrompt(_:)` |
| `sentinelParser` (message envelope) | `MessageEnvelope` |
| `<Renderer />` | `OpenUIView` |

What the conformance tests check against the upstream TypeScript (fixtures in `OpenUITests/Fixtures`):

- **Parser**: one-shot and streaming results are identical for 106 programs, covering every documentation example, the prompt examples, benchmarks and edge cases. The streaming parser is compared after each chunk while the input arrives in pseudo-random chunks.
- **Evaluator**: identical results for 97 expressions and action plans.
- **Libraries**: the chat and standard libraries (84 and 82 components) have the same signatures, descriptions, groups and JSON Schema.
- **Prompts**: byte-identical system prompts for six option combinations.

The renderer behaves like upstream's React components, including details such as tabs and accordions following the content while it streams. One deliberate difference: upstream keeps the first value a `$variable` had while its declaration was still streaming, so `$servings = "2"` can end up as `""` when a render lands mid-declaration. Here a value that still holds its declared default follows the declaration until the user changes it.

## Tests

```sh
# Framework: parser, evaluator, runtime, libraries, prompts and sample scenarios
xcodebuild test -project OpenUI.xcodeproj -scheme OpenUI -destination 'platform=macOS'
xcodebuild test -project OpenUI.xcodeproj -scheme OpenUI -destination 'platform=iOS Simulator,name=iPhone 17 Pro'

# Backend: demo mode, HTTP API, and the Claude and OpenAI integrations against local fakes of their APIs (no keys needed)
cd SampleBackend && npm install && npm test

# Demo app end to end (needs `npm run start:demo` running; skipped otherwise)
xcodebuild test -project OpenUI.xcodeproj -scheme OpenUISample \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -only-testing:OpenUISampleUITests
```

The framework suite also checks that every scripted backend answer parses cleanly with the chat library and that `SampleBackend/openui/system-prompt.md` matches what the library generates.

## Swift package, app components and StreamChatAI

`Package.swift` builds the framework as the `OpenUI` library, with no dependencies, and
`openui-prompt`, which writes the system prompt for the chat library and an app's own
components:

```sh
swift run openui-prompt path/to/prompt.json > instructions.md
```

An app describes its components once, for every platform and for its agent, as portable
definitions: a snake_case `name`, a `description`, `parameters` as a JSON Schema object that
keeps their order in `x-order`, and `events`. `ComponentSchema(portableDefinition:)` reads one
(`place_card` becomes `PlaceCard`), and `ComponentLibrary.addingContent(_:)` adds them wherever
the library's own content goes, such as a `Card`'s children. The prompt config and its options
are documented at the top of `OpenUIPrompt/main.swift`; its examples must parse.

`StreamChatAIOpenUI/` is a package of its own: `OpenUIRenderer`, the renderer StreamChatAI's
generative UI layer (`AIUIHost`) shows replies written in OpenUI Lang with. It keeps a runtime
per reply, places the host's `AIUIComponent`s, sends conversation actions to the host as
`AIUIAction`s with their form values, opens links on the device and runs `Query()` and
`Mutation()` with the host's tools. It reaches StreamChatAI through its public API only, and
for now depends on a `stream-chat-swift` checkout beside this folder.
